## What each doc contains (one line each)

1. **README** — sitemap of the docs, owner, last-reviewed date, "start here" pointers.
2. **Technical SEO** — exact `index.html` head contract (charset, viewport, canonical, theme-color, OG/Twitter, JSON-LD), robots policy, sitemap generation + when to extend `entries`, Core Web Vitals budgets (LCP < 2.5s, INP < 200ms, CLS < 0.1), preconnect rules for Cloudflare Stream/R2 (already shipped).
3. **Schema / JSON-LD** — Organization, WebSite + SearchAction, HairSalon, FAQPage, BreadcrumbList, Offer, VideoObject (for `/watch`), Event (for tournaments). Copy-paste blocks with placeholders.
4. **Per-route meta** — table for every `<Route>` in `src/App.tsx` (Index, /barbers, /watch, /tournaments, /vault, /grants, /book-barber/*, /barber/:id, /battle/:id, etc.) with the required title pattern, description pattern, canonical rule, and JSON-LD list. Calls out which routes need `react-helmet-async` and which inherit from `index.html`.
5. **Social previews** — image specs (1200×630, < 1MB, brand-safe), per-route OG image strategy, the LinkedIn/Slack/FB no-JS limitation already noted in BOOKING_SEO_STRATEGY §7, decision rule on when SSR/pre-render is worth it.
6. **Analytics & KPIs** — event catalogue in `seo_events` (names, props), GA4/Ads/Pixel mapping, the dashboards to build, weekly 15-minute review checklist, the KPI table from BOOKING_SEO_STRATEGY moved/promoted.
7. **Content ops** — editorial calendar template (the 12-week one already drafted, promoted into a living doc), brief template for new city/service pages, internal-linking rules (hub → city → service), QA checklist before publishing a new programmatic batch.
8. **International expansion** — hreflang implementation pattern, `/es/`, `/pl/`, `/uk/` URL strategy, which 5 metros to clone first per market, translation workflow, country-targeting in GSC.
9. **Monitoring & incidents** — GSC + Semrush alerts to set up, ranking-drop runbook (algorithm update vs technical regression vs content decay), deindex recovery steps, the kill/merge rule for thin pages (already in §6 of booking doc).
